# EduClip 아키텍처 명세

목표 명세서. 살아있는 문서 — 단계별로 점진적으로 업데이트됩니다.

---

## 1. 기관(Institution) 모델

기관은 최상위 객체입니다. 하나의 EduClip 인스턴스는 여러 기관을 운영합니다. 기관의 방향성은 목표(Goal) 계층으로 정의됩니다.

### 필드

| 필드 | 타입 | 설명 |
| ---- | ---- | ---- |
| `id` | uuid | 기본 키 |
| `name` | string | 기관명 |
| `slug` | string | URL 슬러그 (고유) |
| `settings` | jsonb | 기관별 설정 (포트폴리오 임계값 등) |
| `createdAt` | timestamp | |
| `updatedAt` | timestamp | |

### 거버넌스

모든 기관에는 고영향 결정을 감독하는 **관리자 보드**가 있습니다. 보드는 인간 감독 레이어입니다.

**V1: 단일 관리자.** 한 명의 인간 운영자.

#### 보드 승인 게이트 (V1)

- 새 에이전트 배치 (에이전트 추가)
- 교육 전략 초기 수립 (상위 에이전트 제안 → 보드 승인 후 실행)
- 예산 변경

#### 보드 권한 (항상 사용 가능)

- 기관 레벨 예산 설정 및 수정
- 임의 에이전트 일시 정지/재개
- 임의 작업 일시 정지/재개
- 전체 작업 관리 접근 (생성, 수정, 삭제, 재할당)
- 임의 에이전트 결정 재정의
- 임의 레벨의 예산 수동 변경

---

## 2. 에이전트(Agent) 모델

모든 직원은 에이전트입니다. 에이전트는 교육 기관의 실무 인력입니다.

### 에이전트 역할 유형

| 역할 | 설명 |
| ---- | ---- |
| `curriculum_designer` | 커리큘럼 설계 및 학습 목표 수립 |
| `tutor` | 수강생 1:1 질의응답 및 지도 |
| `evaluator` | 과제·포트폴리오 평가 및 피드백 |
| `operations` | 스케줄 관리, 알림, 반복 업무 자동화 |
| `analyst` | 학습 데이터 분석 및 인사이트 제공 |

### 어댑터 모델

에이전트는 **어댑터 타입**과 **어댑터별 설정 블롭**을 가집니다.

#### EduClip 프로토콜 (플랫폼 수준)

플랫폼 수준에서 EduClip이 추적하는 항목:

- 에이전트 ID, 이름, 역할
- 소속 기관 및 상위 에이전트 (조직도)
- 현재 할당된 작업
- 예산 소진율 및 하트비트 상태

---

## 3. 작업(Task) 모델

### 작업 계층 구조

```
기관 목표 (Institution Goal)
  └── 프로젝트 (Project)
        └── 마일스톤 (Milestone)
              └── 작업 (Task)
                    └── 서브태스크 (Subtask)
```

### 작업 상태 흐름

```
open → assigned → in_progress → review → closed
                                       └── blocked
```

### 티켓 시스템

모든 에이전트 대화는 티켓과 연결됩니다. 티켓은 다음을 포함합니다:

- 전체 대화 스레드
- 도구 호출 로그 (불변)
- 에이전트 결정 근거
- 소요 토큰 및 비용

---

## 4. 하트비트 시스템

에이전트는 스케줄에 따라 깨어나 작업을 확인하고 실행합니다.

### 하트비트 흐름

1. 스케줄러가 에이전트를 깨웁니다.
2. 에이전트가 현재 컨텍스트와 목표를 수신합니다.
3. 에이전트가 다음 작업을 체크아웃합니다.
4. 에이전트가 작업을 실행하고 결과를 보고합니다.
5. 플랫폼이 토큰 소비를 기록합니다.
6. 예산 한도 도달 시 에이전트가 자동 중단됩니다.

### 원자적 체크아웃

작업 체크아웃과 예산 적용은 원자적으로 처리됩니다. 중복 작업과 비용 초과가 발생하지 않습니다.

---

## 5. 포트폴리오 유사도 분석

### 목적

수강생 제출물의 모방 및 양산형 복붙을 구조적으로 탐지합니다.

### 파이프라인

```
제출물 텍스트
  └── 임베딩 생성 (OpenAI text-embedding-3-small, 1536차원)
        └── pgvector 저장
              └── 코사인 유사도 비교 (동기 기수 + 과거 제출물 전체)
                    └── 임계값 초과 시 플래그 및 관리자 알림
```

### 임계값 설정

기관별로 유사도 임계값을 설정할 수 있습니다 (기본값: 0.85).

```json
{
  "similarityThreshold": 0.85,
  "alertOnSuspicious": true,
  "requireFollowUpQuestion": true
}
```

## 6. RAG 파이프라인

### 구성 요소

| 구성 요소 | 역할 |
| --------- | ---- |
| `packages/rag/` | 임베딩 생성 및 검색 |
| `packages/rag-worker/` | BullMQ 기반 비동기 임베딩 처리 |
| PostgreSQL + pgvector | 벡터 저장 및 유사도 검색 |

### 문서 처리 흐름

```
교육 자료 업로드
  └── 청크 분할 (RecursiveCharacterTextSplitter)
        └── 임베딩 생성 (BullMQ 큐)
              └── pgvector 저장
                    └── 에이전트 질의 시 관련 청크 검색
```

## 7. 멀티 테넌시

모든 엔티티는 `institution_id`로 범위가 지정됩니다. 단일 배포 환경에서 여러 기관을 완전히 격리된 데이터와 감사 로그로 운영합니다.

- Row-Level Security (RLS) 정책 적용
- 에이전트 간 데이터 격리 보장
- 기관별 독립적인 예산 및 설정
